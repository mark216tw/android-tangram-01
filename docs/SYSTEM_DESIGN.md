# 系統設計文件

## 1. 目的

`mini七巧板` 提供簡單、離線且適合手機操作的七巧板體驗。首版重點是正確的標準拼片幾何、清楚的目標剪影、精準但不苛刻的吸附，以及容易理解的關卡進度。

## 2. 範圍

### 已包含

- 首頁、遊戲說明、設定、關卡選擇及遊戲畫面
- 12 個本機動物關卡
- 七塊標準拼片操作
- 提示、重置、完成判定、計時及最佳紀錄
- 主題、音效及進度持久化
- 手勢導航與三鍵導航安全區

### 不包含

- 帳號、雲端同步或社群功能
- 網路排行榜
- 廣告或應用程式內購
- 關卡編輯器
- 跨裝置進度同步

## 3. 使用者角色

本系統只有單一本機玩家角色，不需要登入或權限分級。

## 4. 功能需求

| 編號 | 需求 |
| --- | --- |
| FR-01 | 玩家可從首頁開始遊戲、查看說明、修改設定及將 App 移至背景。 |
| FR-02 | 玩家可查看關卡鎖定、完成及最佳時間狀態。 |
| FR-03 | 第一關預設解鎖，完成關卡後解鎖下一關。 |
| FR-04 | 玩家可點擊選取及拖曳未鎖定拼片。 |
| FR-05 | 玩家可將拼片向左或向右旋轉 45 度。 |
| FR-06 | 玩家可翻轉平行四邊形。 |
| FR-07 | 拼片接近相容目標時自動吸附並鎖定。 |
| FR-08 | 玩家可使用提示及重置。 |
| FR-09 | 系統保存最佳時間、解鎖進度及偏好設定。 |
| FR-10 | 玩家可選擇系統、淺色或深色模式。 |
| FR-11 | 玩家可開關吸附音效。 |

## 5. 非功能需求

| 類別 | 需求 |
| --- | --- |
| 相容性 | 支援 Android 8.0（API 26）以上。 |
| 離線 | 核心功能不得依賴網路。 |
| 效能 | 拖曳時應維持即時 Canvas 更新，不執行磁碟 I/O。 |
| 可用性 | 主要觸控元件至少約 48dp，底部操作不得被系統導覽列遮住。 |
| 外觀 | 淺色與深色模式都須維持文字、剪影與拼片的辨識度。 |
| 隱私 | 不蒐集、不上傳個人資料或遊戲行為。 |
| 維護性 | 幾何、關卡、狀態及持久化責任需清楚分離。 |

## 6. 畫面設計

### 首頁

- 上方使用與 App 圖示一致的七巧板圖案。
- 中央顯示 `mini七巧板` 品牌與標語。
- 下方以紙藝卡片區分主要及次要操作。
- 首頁返回鍵及「結束遊戲」都將工作移至背景。

### 關卡選擇

- 自適應網格顯示 12 張關卡卡片。
- 卡片顯示編號、動物名稱、鎖定狀態與最佳時間。
- 網格底部包含 Scaffold 與系統導航列安全間距。

### 遊戲畫面

- 上方工具列顯示關卡、計時、提示與重置。
- 中央 Canvas 上半部為目標剪影，下半部為初始拼片區。
- 下方固定工具列提供左轉、翻面及右轉。
- 吸附拼片降低些微透明度並鎖定操作。

### 設定

- 顯示模式使用單選控制。
- 音效使用 Switch 控制。
- 所有設定變更立即生效並保存。

## 7. 核心資料模型

```kotlin
data class Vec2(val x: Float, val y: Float)

data class PieceSpec(
    val kind: PieceKind,
    val vertices: List<Vec2>,
    val color: Long
)

data class Pose(
    val center: Vec2,
    val rotation: Int = 0,
    val flipped: Boolean = false
)

data class Level(
    val id: Int,
    val name: String,
    val targets: Map<PieceKind, Pose>
)
```

`PlayingPiece` 另保存 `snapped` 及 `snappedTarget`，避免相容拼片吸附到同一目標。

## 8. 狀態轉換

```text
未選取
  ├─ 點擊拼片 → 已選取
  └─ 點擊空白 → 未選取

已選取
  ├─ 拖曳 → 移動中
  ├─ 旋轉/翻面 → 已選取（姿態更新）
  └─ 接近相容目標 → 已吸附

已吸附
  ├─ 尚有拼片 → 等待其他拼片
  └─ 全部吸附 → 關卡完成
```

## 9. 設計決策

### 使用 Canvas 而非圖片元件

拼片需要任意移動、旋轉、翻面、點擊測試及跨裝置等比例縮放。以頂點資料配合 Canvas 可讓繪製與判定共用同一幾何模型。

### 使用中心距離與姿態吸附

首版每關已定義每塊拼片目標，因此中心距離、旋轉與翻面判定較遮罩像素比對簡潔且穩定。相同尺寸三角形另以相容規則允許交換。

### 使用 DataStore

資料量小且皆為偏好或簡單進度，不需要關聯式查詢，因此 Preferences DataStore 比 Room 更合適。

### 使用 ToneGenerator

吸附音很短且不需要外部音訊資源。`ToneGenerator` 可減少 APK 資源及載入流程；若未來需要品牌音效，可改用 `SoundPool`。

## 10. 已知限制與擴充方向

- 關卡資料目前直接寫在 Kotlin 原始碼，可改為 JSON 或關卡編輯工具輸出。
- 當前遊戲不保存進行中的關卡狀態。
- 音效目前為系統提示音，可替換為自訂音訊。
- 可增加 Compose UI 測試與實機截圖測試。
- 可加入無障礙語意、色盲配色或震動回饋。
